## Session 4 (Back/forward across tabs)
### Discussion
- User: the back/forward buttons work for whole pages, "but i want it to navigate between tabs as well, so if i am in seeding and go to matches and click back i want to go to seeding".
- Cause: tabs are stored via server persistence (`useTab`) and don't touch the URL/history, so browser back skipped them.

### Changes
- `TabsPersistanceManager.js` (`useTab`): tab switches now push a history entry and react to `popstate`:
  - Each tab group stores its value under `window.history.state.tabs[phase]` (phase is e.g. `season`, `quals1`, `groups1`), merged so multiple tab groups on one page coexist.
  - On mount the current tab is written with `replaceState`; `handleChangeTab` uses `pushState`; a `popstate` listener restores the tab from the entry state.
  - Server persistence (`saveTag`) is unchanged, so reloads still remember the last tab.
- The existing toolbar back/forward buttons already call `window.history.back()`/`forward()`, so they now also step through tab changes.

### Notes
- Works because `window.history.back()` and the tab `popstate` listener share the same browser history. Cross-page navigation remains full-page `window.location`, which is what the initial history entry is based on.
